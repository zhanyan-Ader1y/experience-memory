# Codex 与 Claude Code 分阶段接入设计

日期：2026-10-15。用户已审阅并选择逐任务子 Agent 执行首个 B0 计划，运行基线已完成；[交付验证](../../verification/full-function.md)记录最终证据。尚未安装插件、启用可信身份、修改宿主信任或切换正常项目。

## 1. 目标与实施边界

采用共享记忆内核和两个薄宿主适配层，顺序为可重复运行基线、Codex 原生验收、双宿主隔离机制、Claude Code 可行性与适配、跨宿主验收。现有五工具、Mem0 仓储、读取回执、有效采用/U、确定性选择、检查点与恢复继续复用。

原留存协议继续以 [2026-10-12 设计](2026-10-12-mem0-compaction-retention-design.md) 为依据；本文件扩展宿主范围，并约束新增的身份和生命周期适配，不将历史文档中的 Codex 契约当作 Claude Code 契约。实施导航保留在 [既有后续计划](../plans/2026-10-14-experience-memory-followup-plan.md)。

排除：自动经验提炼、跨项目默认共享、子 Agent 独立生命周期、跨机器并发保证、云端宿主、新 OS 支持、控制记录归档、通用宿主框架、安装包与发布。

## 2. 全局约束

- Python 声明下限为 3.10；当前新增运行基线使用 Windows/Python 3.13.1，仅报告实际测试过的版本。
- MCP SDK 固定为 mcp==2.3.0；不得通过降级业务接口迁就全局 MCP 1.28.1。
- Mem0 是非核心正文、摘要和控制集合的持久来源；插件本地只保存标识、状态、指纹和锁。
- 完整 additionalContext 默认不超过 8192 UTF-8 字节，包含固定协议、项目核心、句柄、标记及区域包装；不是 token 预算。
- 核心自身超预算时失败，不截断核心；非核心按 P1/P2/P3、最旧 U、ASCII ID 顺序整条淘汰。
- 仅确认的有效采用推进 U；查询、读取、恢复、压缩和同一逻辑操作重试不推进 U。
- pending/unknown 不是成功；先定案原操作，不因搜索暂时无命中另起写入。
- 同项目经验可在 Codex 与 Claude Code 间共享；回执、句柄、U、窗口和检查点不跨宿主会话共享。
- 可信身份来自经过核验的宿主通道，不来自工具参数、任意句柄、启动 cwd 或历史会话扫描。
- 支持范围限单机器协调写入；不声明远端事务、CAS、跨机器锁或断电耐久。
- 不修改全局 Python、旧插件、正常项目配置或宿主信任；原生启用、在线合成写入及项目切换分别取得范围明确的授权。
- 不打包、不发布；未经明确要求不提交、推送或创建 Git 远程。

## 3. 设计时事实与证据分级（实施前快照）

源码已实现读写内核；生产 MCP 身份仍默认拒绝。当前系统 Python 3.13.1 安装 MCP 1.28.1；2026-10-15 只读包索引查询确认 MCP 2.3.0 可用，但尚未创建新虚拟环境或安装依赖。

先前当前环境补充源码路径后的回归为发现 94 项、84 通过、7 跳过、3 个测试模块因 SDK 不匹配导入失败。历史文档的 102 项结果不是本次复现结果，后续以新环境实际发现和运行数量为准。

所有能力分别保留四种证据：本地单元、SDK/Hook 契约、真实 Mem0 合成 API、真实宿主。skip 只表示未验证；证据 JSON 的结构一致性不能证明原生材料真实性。

## 4. 三个独立实施单元

### A. 运行基线与 Codex 原生闭环

先实施 [运行基线计划](../plans/2026-10-15-runtime-baseline-plan.md)，不改现有身份与恢复语义。基线可重复运行后，单独审阅 Codex 探针实施方案，再在专用合成项目核验身份来源、压缩关联、立即注入、失败行为和额外落盘。

通过探针才实现与证据匹配的 Codex 适配。宿主不足时给出 unsupported 或 unverified，不通过放开布尔开关强行完成。原生探针启动或模型请求不包含在离线基线授权中。

### B. 双宿主隔离与 Claude Code 接入

先消除会话标识、操作标识和本地锁目录冲突，再开展 Claude Code 可信身份与严格恢复可行性探针。可行后实施其薄适配层；不可行时保持对应能力关闭并记录明确原因，不降低已确认安全要求。

### C. 跨宿主验收与项目级切换

在两类宿主各自通过相关门槛后，验证同项目共享经验、不同会话隔离、同机写入协调和逐项目回退。一个宿主验收成功不代表另一个宿主成功。先合成项目，后经审阅切换正常项目。

B、C 的逐行实施计划在前置证据成立后单独编写，避免把未核验的宿主字段写成实现事实；本文件已确定它们必须遵守的边界和验收结果。

## 5. 最小宿主边界

保留 interfaces → application → domain、infrastructure → domain 及唯一 bootstrap。

| 单元 | 输入与输出 | 不负责 |
| --- | --- | --- |
| 可信身份适配 | 宿主可信输入转换为已核验的项目、宿主类型、机器与原生会话身份 | 根据工具参数补造身份 |
| 生命周期适配 | 宿主原生事件转换为启动、续接、检查点准备与恢复动作 | 维护自己的 U、活动集合或淘汰算法 |
| 输出适配 | 应用结果编码为该宿主、该事件真正支持的上下文或失败输出 | 宣称不支持的全局阻断能力 |
| 记忆与留存内核 | 核验、幂等写入、采用、确定性选择、检查点与恢复 | 依赖 Codex/Claude SDK 或原生事件名 |

不预先建设动态注册、插件发现或通用事件总线。具体公共方法签名在两个宿主的实际差异核验后确定；在此之前保持既有应用 API，不新增未经使用的接口。

## 6. 项目与会话隔离

项目键不包含宿主类型，相同项目仍映射到相同 Mem0 经验范围。会话控制身份必须区分宿主类型、机器与原生根会话，不直接以裸 session_id 作为跨宿主控制键。恢复相同原生会话必须得到稳定身份，不能使用每进程随机 UUID 破坏 resume。

读取回执、绑定、U、窗口和检查点归属于完整会话身份；逻辑操作重试在同一会话范围内复用调用方 operation_id，不能误命中另一个宿主的操作日志。

同一台机器上的两类客户端必须使用同一个可信项目协调目录；不能让两个不同的 PLUGIN_DATA 目录分别持锁而宣称互斥。项目写入仍受共同项目锁约束，会话控制键分别隔离。

修改控制模式时必须显式版本化。旧控制指针不得静默解释为新版绑定，也不得自动复制活动集合；不兼容时明确拒绝并要求经审阅重新绑定。经验记录不因控制模式改变而自动迁移、复制或删除。

## 7. Claude Code 已核验的文档约束

### 7.1 入口与配置隔离

Claude Code 的 manifest 为 .claude-plugin/plugin.json，默认 MCP 文件为 .mcp.json。当前根 plugin.json 的 com.openai 扩展不构成 Claude 接入。

Claude Code 默认还加载 hooks/hooks.json；不能只新增 Claude manifest 就让现有 Codex Hook 自动运行。正式接入时分别安排宿主 Hook 入口与配置，并验证默认路径与显式路径的合并，避免重复注册和误执行。源码直接加载可用于专用测试，不需要发布 marketplace。

### 7.2 可信 MCP 身份

已核对的 MCP 文档未明确提供外部 stdio server 的可信逐请求 session_id/cwd 通道。CLAUDE_PROJECT_DIR 和 roots/list 不证明该请求属于哪个原生根会话。文档未保证不等于绝对不可能，但也不能据此启用身份适配。

若需要 Hook 与 MCP 之间的可信桥接，必须先有独立方案，证明准确请求关联、参数绑定、有效期、防重放以及跨会话拒绝。仅把句柄写入可读文件或由工具携带身份不满足要求。

### 7.3 压缩关联与失败语义

当前文档列出的 PreCompact 特有输入为 trigger、custom_instructions，PostCompact 为 trigger、compact_summary，不能假定存在专用压缩 UUID。session_id + trigger 不能区分连续两次同类压缩；本地生成序号不能单独证明某个恢复事件属于它。

PreCompact 可以通过文档支持的 decision=block 或退出码 2 阻止压缩，但会忽略 continue/systemMessage。主动自动压缩被阻止后可能继续未压缩会话，不能把阻止压缩等同于停止整个模型会话。PostCompact 无决策控制，不能作为失败后的全局停止点。

SessionStart 的错误退出码不保证停止会话；通用 continue 字段与事件描述的语义存在需要实测澄清的边界。不能直接复用现有 Codex failure JSON 声称严格停止。

未能证明本次关联、立即注入及必要阻断行为时，不声明严格恢复支持，不使用最近一次 ready 检查点替代本次。

### 7.4 注入预算与证据

当前文档对 additionalContext 等单个字符串设置 10000 字符上限，超限可能落盘并替换为路径和预览，且没有提高上限的配置。本项目 8192 UTF-8 字节上限继续保持，仍须在目标版本核验完整注入与额外落盘。

只记录所需的白名单事件元数据、字节数和指纹，不持久化完整 Hook 输入；PostCompact 的 compact_summary、transcript_path 指向的历史和真实正文均不得复制为本地经验缓存。

## 8. 恢复、幂等与截止时间

恢复路径继续核验本次检查点、当前经验状态和指纹，按完整预算选择集合，确认实际活动窗口后才发布上下文。P1 未知或版本异常阻断依赖动作；P2/P3 降级必须说明原因。失效、淘汰项不能从旧摘要自动复活。

同一逻辑操作收到 pending/unknown、响应丢失或本地发布中断时，仅定案原操作；明确失败不伪装为 unknown。身份、范围和权限失败不能退化成空库成功。

所有锁等待、网络读取、选择和输出共享绝对截止时间，内部截止短于宿主超时并预留输出时间。先测量再决定是否增加有界并发；若引入线程，显式传递当前绝对截止时间，不能丢失 ContextVar 约束。不引入本地正文缓存。

## 9. 验收门槛

| 门槛 | 成立条件 | 不成立时 |
| --- | --- | --- |
| B0 运行基线 | 专用环境固定 SDK；独立源码测试入口；离线诊断准确；全部实际发现的离线测试通过 | 不运行原生安装与正常项目切换 |
| C1 Codex 来源 | 真实逐请求身份与跨会话/跨项目拒绝证据 | MCP 继续明确拒绝 |
| C2 Codex 留存 | 手动、自动、连续两次、紧接请求、输出和失败行为证据 | 不声明原生恢复支持 |
| H1 双宿主隔离 | 相同原生会话/操作 ID 不碰撞，共同项目锁生效 | 不启用共享写入 |
| A1 Claude 可行性 | 可信调用身份、唯一压缩关联、立即注入和必要失败控制有可核验证据 | 对应能力 unsupported/unverified，不实现猜测性适配 |
| A2 Claude 适配 | 按事件结果编码、独立清单/Hook、完整工具与恢复原生验收 | 不切换 Claude 正常项目 |
| X1 跨宿主试用 | 项目共享、会话隔离、竞争冲突、单端停用、逐项目回退均验证 | 保留原责任方与配置 |

跨宿主场景必须覆盖 A 写/B 读后重新采用、A 回执不能被 B 使用、同名经验跨项目拒绝、A 失效后 B 不恢复旧版本、同时维护冲突和单端停用不影响另一端。

## 10. 文档与执行交接

第一阶段只实施运行基线与诊断，不改可信身份、压缩语义、宿主配置布局和锁键。设计与计划先由用户书面审阅；批准后推荐在本会话按任务执行，每项遵循失败测试、最小实现、回归和审阅。

没有首次 Git 提交是当前事实，不因计划落盘自动建立提交。审阅检查点以工作区差异和测试结果交付，提交、推送和原生启用仍分别等待明确要求。
