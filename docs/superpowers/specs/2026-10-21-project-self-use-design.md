# Experience Memory 本项目双宿主自用设计

日期：2026-10-21。

状态：用户已确认“双端共享项目经验、分阶段启用；先 Codex，后 Claude Code”的设计方向。本轮落实设计与第一阶段实施计划，不等于批准实施、原生调用、在线写入或项目切换。

## 1. 目标与完成定义

让 Experience Memory 成为开发本仓库时实际使用的经验系统，而不是只在测试夹具中运行。复用现有记忆、读取回执、有效采用/U、窗口、检查点和恢复内核，不重写业务层，不用已安装的其他 Mem0 插件代替本产品验收。

最终闭环：

```text
真实开发任务 → 按问题检索 → 精读核验 → 实际采用后登记
    → 实现和验证 → 提议可复用经验 → 经确认写入并真实回读
    → 后续真实任务/会话再检索采用 → 发现错误时更新或失效
```

分别记账两个里程碑：

1. **开发经验闭环**：本产品在真实宿主中完成绑定、搜索、读取、维护、有效采用，以及后续会话的再次使用。
2. **上下文留存闭环**：本产品在该宿主中通过本次边界、立即注入、失败行为、完整预算和连续压缩验证。

基础工具通过不代表严格恢复通过。若宿主无法满足某项能力，明确 unverified/unsupported，并由用户决定是否接受受限试用；不自动缩减本设计的最终目标。

## 2. 已有事实与当前缺口

以 [兼容矩阵](../../compatibility.md)、[C1-T交付](../../verification/codex-c1-appserver-transport.md) 和实际代码为准。

- Mem0 仓储、五工具、绑定、回执、U、留存及恢复内核已有实现与分层证据。
- `__main__.py` 的生产 MCP 仍调用默认拒绝的 `request_host`。受控 Codex 解析器存在不等于生产适配启用。
- C1-T 离线候选已交付；`C1_APPSERVER_NATIVE_ACCEPTANCE_PENDING` 不变。旧 exec 为 `C1_NATIVE_EXEC_APPROVAL_UNSUPPORTED`，不能改成 AutoReview 或绕过人工审批。
- 当前没有根 `.experience-memory.json`。AGENTS/CLAUDE 和 verify-offline 是开发指导，不是本产品已接入的证据。
- 真实 Codex 目标版本、当前旧插件配置及其责任范围，本轮未调用/读取以重新验收。历史 0.163.0 合同不保证实际目标版本仍相同。
- 共同锁、跨宿主控制身份与 Claude 原生接入仍待 H1/A1/A2。不能现在并行开放两端写入。
- 历史原生探针授权已经消耗。本设计不补发任务名额，也不复用原授权。

主要工作是宿主接入、授权和自用验收，不是增加通用技能集合或新经验存储。

## 3. 方案选择

采用 **Codex 先自用，再接 Claude，最后跨端验收**。

理由：Codex 已有受控元数据观察、严格解析、本地 SDK 拒绝合同与 app-server 离线候选，能直接续接下一门槛。Claude 优先会先面对尚未证明的请求身份桥接。双端同时安装会混合身份、锁、恢复和旧责任方四类故障。

保持 [双宿主设计](2026-10-15-dual-host-integration-design.md) 与 [阶段路线](2026-10-18-development-roadmap-design.md) 的安全语义。新增自用里程碑，不用它们跳过 C1/C2/H1/A1/A2/X1。

## 4. 项目身份、配置和固定核心

### 4.1 稳定项目身份

本仓库自用候选显式指定 `project_scope: "local:experience-memory"`，不依赖目录名、工作目录或新增 Git 远程。此身份只分配给本逻辑项目；无关项目不得复制使用。同项目已审阅的检出可共享经验，宿主请求仍须核对自己绑定的规范化 Git 根。

显式身份在以后增加远程时不自动改变。若要迁移身份，另行审阅映射与数据范围；不自动迁移旧 Mem0 命名空间。两端使用相同项目经验身份，不把宿主类型加入经验项目键。

### 4.2 被动配置候选

第一阶段只新增 `examples/self-use/project-config.preview.json`，不创建根自动发现配置。候选 `enabled=false`，`shared_scope=false`，`namespace_mapping=null`，官方 Mem0 地址和现有超时/预算不变；不含密钥、用户目录、会话标识或机器绝对路径。

候选是原 Config 模式，不是新的启用凭证。未来变成实际配置前须重新核对当时的宿主能力、配置差异与回退；翻转 enabled 不能开放默认拒绝的身份入口。

### 4.3 精简固定核心

第一阶段新增 `docs/self-use/core.md`，只包含固定项目导航与自用边界，不记任务日志、经验条目或经验摘要。它指向 AGENTS 和任务导航，不复制完整 AGENTS/CLAUDE/计划。

项目核心不超过 1024 UTF-8 字节；按现有 bootstrap 拼接方式，通用 `prompts/core.md` 加换行及项目核心合计不超过 4096 UTF-8 字节。这只是准备阶段的留白检查，不证明包含句柄、正式区域、标记和包装的完整注入已通过 8192 字节合同。原生接入仍必须走生产的完整预算核验。

FileCoreLoader 不递归展开 Markdown 链接。宿主开发规则入口仍需正常加载 AGENTS/CLAUDE；不能把导航链接解释成这些文件已注入模型。

## 5. 数据流与经验维护

### 5.1 任务开始和范围变化

先校验固定核心和当前宿主绑定，再按当前问题检索；不全库遍历。成功无命中、身份失败、认证失败及其他查询失败分别报告。

候选需精读核验范围、状态、证据和指纹。只有实际支持了判断、代码或测试，才以当前有效读取回执登记采用。不得因搜索命中就增加 U。

### 5.2 任务结束

先完成实现与验证，再在当前会话提议值得保存的经验，由用户明确确认本次候选后维护；不默认授权未来无限自动写入。

纳入候选应包含具体触发、适用条件、可执行动作和可定位验证来源。已有代码/文档能完整表达的规范不重复建立第二份正文，必要时只保留触发和导航。一次性进度、测试总数和未验证推断不自动作为 active 经验。

经语义与稳定 ID 验重后调用本产品 memory_write，只有真实回读 confirmed 才报告已保存。pending/unknown 续接原 operation_id 和原参数，不重新 add。更新和失效沿用经验标识并核对最新指纹。

### 5.3 后续会话与纠错

新会话重新绑定，不能拿旧句柄/回执冒充自己的身份。经验可以共享，但必须重新读取核验，确实使用后由新会话独立登记。错误经验经明确维护后失效，旧摘要、窗口或检查点不能使其复活。

候选和经验正文不进入本地待办文件、接力缓存、运行日志或验收报告。本仓库设计与代码文档仍正常维护，但不作为工具不可用时的替代记忆库。

## 6. 宿主和协调边界

- Codex 与 Claude 共享同项目经验，不共享会话句柄、读取回执、U、活动窗口或检查点。
- 双端同时共享写入前必须完成 H1：宿主类型/机器/原生根会话组成控制身份，操作幂等隔离，两个宿主使用同一可信项目协调目录。
- 当前进程内部 mutex、不同 PLUGIN_DATA 下各自持锁、或模型承诺串行都不等于共同项目锁。
- Claude 不能直接继承 Codex 的 metadata、Hook、清单和失败语义。A1 先验证身份/请求关联、生命周期与输出，再实现可行部分。
- 句柄文件、工具自报身份、启动 cwd、最近会话或历史 transcript 不能替代可信通道。

## 7. 旧插件责任与回退

旧插件现状在第一阶段保持 **未盘点/未切换**；不从工具名称猜测实际配置或缓存行为。后续经明确授权，只读取必要配置结构并记录脱敏标识、目标路径与摘要，不收集密钥或正文。

本产品成为某宿主中本项目的责任方之前，必须提供：启停配置的精确差异；唯一责任方及是否有旧自动检索/写入/Hook；共同协调位置；验证步骤；逐项目回退。

不全局卸载旧插件、不删除其缓存或云端数据、不擅自合并命名空间。切换失败则停止本项目的新入口，按已审阅前态恢复；配置被用户更改时先报告冲突，不能覆盖。回退不以删除已确认云端经验、重置 U 或退还原生尝试名额来假装恢复。

## 8. 分阶段交付

| S4 Claude 自用 | A1/A2 可行性与薄适配、合成验证、项目级切换 | Claude 独立完成经验和留存能力验收；限制明确 | 双端闭环 |

## 9. 全局约束

以下各行同时适用于第一阶段计划：

- Python 声明下限 >=3.10；当前本机运行证据为 Windows/Python3.13.1；MCP 固定 mcp==2.3.0，不新增依赖或修改全局 Python。
- Mem0 是非核心正文、摘要和控制集合的持久来源；本地只保存运行时定义的标识、状态、指纹和锁。
- 完整 additionalContext 默认最多 8192 UTF-8 字节，包含固定协议、项目核心、句柄、标记和包装；核心超限失败，不截断。
- 仅确认的有效采用推进 U；查询、读取、恢复、压缩和同一逻辑操作重试不推进 U。
- pending/unknown 不是成功；先定案原 operation_id，不因搜索暂时无命中另起写入。
- 第一阶段不修改 src/、scripts/、hooks/、根产品 skills/、生产清单、根自动发现配置、宿主 MCP/Hook 配置或信任/权限设置。
- 第一阶段不调用真实 Codex（包括版本/schema/只读 RPC/线程）、模型、Mem0、账户/额度或信任接口；不读取真实凭据值。
- 真实原生诊断、在线合成写入、实际安装和本仓库项目切换分别取得明确授权；thread/start 可能预热外部连接，不是纯本地只读。
- 同项目经验共享不等于控制状态共享；共同锁与隔离通过前不开放双端共享写入。
- 不打包、不发布，不提交、推送、合并、创建远程或 worktree；保留已有快照与失败证据。

## 10. 验证与报告

S0 只验证候选及本地入口：配置可由现有 Config 读取、身份稳定且不从目录猜测、固定核心有界、预览未被自动发现、doctor 不创建远端绑定/指针、不把本地准备升级原生能力。

未来原生验收使用合成数据隔离风险，然后才在获授权的本项目范围执行真实自用。正常经验不拿来反复模拟错误。应用/SDK/本地假宿主、真实 Mem0、真实原生宿主及真实开发使用分别记证。

闭环报告仅记录必要的宿主/项目/会话标识摘要、operation_id、真实回执/记录标识、状态、指纹、验证来源及采用所在任务引用，不复制正文。自述“已遵守”不证明模型确实采用，至少结合实际实现或测试中的使用位置。

工具/身份或远端不可用时报告未完成，不回退到其他 Mem0 插件、全用户查询或本地备用库。第一阶段完成的措辞只能是“接入准备完成”，不能是“本项目已开始自用”。
